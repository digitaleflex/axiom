# Master Prompt 01 — Axiom Product UI Brief

You are a Senior Product Designer specialized in developer-first SaaS, DevOps, cloud infrastructure and deployment platforms.

## Context

The product is **AXIOM**.

Axiom is a deployment and application hosting platform.

Positioning:

> Axiom transforms a GitHub repository into a deployed application.

Core pipeline:

GitHub → Repository → Repository Analysis → Stack Detection → Application Profile → Deployment Plan → Build → Runtime → Networking → Domain / SSL → Health Check → LIVE.

Axiom combines a modern developer experience with application and infrastructure management.

## Objective

Produce a complete Product UI Brief that becomes the source of truth for Axiom interface design.

Do **not** design screens yet.

Analyze and define:

1. Product positioning
2. Target users
3. Primary persona
4. Secondary personas
5. Core user jobs
6. Main user goals
7. User frustrations
8. Product promise
9. UX principles
10. Desired emotional qualities
11. Information hierarchy
12. Core product areas
13. Primary navigation
14. Critical user journeys
15. Trust signals
16. Important system states
17. Empty states
18. Loading states
19. Error states
20. Success states
21. Deployment-specific states
22. Infrastructure-specific states
23. UX risks
24. Design opportunities
25. Anti-patterns to avoid

The central experience must remain:

Repository → Analyze → Configure → Deploy → Observe → LIVE.

The user must understand what Axiom is doing and why each step exists.

## Deliverable

Produce:

# Axiom Product UI Brief
## Product Definition
## Users
## Jobs To Be Done
## UX Principles
## Information Architecture
## Core Journeys
## Product Areas
## UI States
## Design Opportunities
## Risks
## Design Constraints
## Success Criteria

End with:

**Design decisions that must remain consistent across every screen.**

Do not generate interface designs at this stage.

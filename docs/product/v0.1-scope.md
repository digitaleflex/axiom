# Axiom V0.1 Scope

> Issue #26. Product context: [`vision.md`](vision.md), [`scope.md`](scope.md).

## 1. Objective

Axiom V0.1 proves the core product promise: connect GitHub, analyze an application, generate a deployment plan, deploy it to an eligible server, verify health and make it LIVE.

**Target:** GitHub → Detect → Deploy → Live.

## 2. V0.1 Acceptance Journey

Authenticate → Connect GitHub → List repositories → Select repository/ref → Analyze → Application Profile → Select eligible server → Generate Deployment Plan → Review → Create deployment → Observe realtime progress → Build → Deploy → Health verification → LIVE → Return live URL → Inspect logs/events

Every in-scope capability below exists because a step of this journey needs it.

## 4. Out of Scope — Non-goals

| Non-goal | Why excluded from V0.1 |
|---|---|
| Kubernetes-first deployment | premature; V0.1 runtime is Docker/Compose on one server |
| Multi-cloud / multi-region orchestration | one reference server is enough to validate the journey |
| Billing implementation | commercial surface, not needed to prove GitHub → LIVE |
| Agent / expert marketplace | no validated expert model to distribute yet |
| Advanced autonomous infrastructure optimization | automation stays bounded and explicit |
| Generic autonomous software factory | Axiom deploys applications; it does not write them |
| Arbitrary remote shell / arbitrary Docker control from clients | violates bounded-operation security model |
| Fully autonomous destructive operations | destructive actions require explicit human confirmation |
| GitLab and other source-control providers | GitHub only |
| Advanced backup orchestration | outside deployment journey |
| MicroVMs, service mesh, advanced isolation/networking | future architecture options requiring a versioned contract |
| Axiom CLI, Admin Console | post-V0.1 (#22, #73) |

## 5. Explicit V0.1 Runtime Model

Axiom Engine → Runtime Agent → Docker → Traefik → Application Runtime

## 6. Reference Project Validation

V0.1 is validated with **one reference application on one reference server** (#23, #107–#109). Scope is acceptable only if this single reference deployment can exercise every in-scope capability.

## 7. Success Criteria

1. A conforming implementation executes the documented GitHub → LIVE journey using only Axiom Engine contracts.
2. The Cloud Console never communicates directly with Docker, Traefik, PostgreSQL, Runtime Agents or deployment servers.
3. A deployment becomes LIVE only after successful health verification.
4. A failed reference deployment is diagnosable from the Console without SSH.
5. No secret appears in logs, events, errors or the browser after entry.
